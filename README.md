# GA PINN 3D

Параметризованная физически-информированная нейросеть (PINN), решающая стационарные
уравнения Навье-Стокса (несжимаемая ньютоновская жидкость) для **произвольной**
3D-геометрии сосуда, заданной облаком точек из STL-мешей. Предполагается, что одна обученная модель работает для семейства разных геометрий, без переобучения под
конкретный сосуд.

## Идея и методология

### Жёсткое наложение граничных условий через функции расстояния

Вместо softsoft-штрафов за нарушение граничных условий (как в классическом PINN)
условия зашиваются в саму параметризацию решения, так что они выполняются точно
при любых весах сети:

- Одна голова сети (`linear_out_phi`) регрессирует сразу две функции расстояния:
  - **phi_1** — расстояние до стенок сосуда (0 на стенке, растёт к центру потока);
  - **phi_2** — расстояние до стенок **и** до плоскости входа одновременно (0 на
    стенке и на входе).
- Скорость собирается как

  ```
  v = v_pred * phi_2  +  phi_1 * norm_in * (Q / S / v_mean)
  ```

  Первое слагаемое — свободное предсказание сети `v_pred`, обнулённое на стенках
  и на входе через `phi_2`. Второе — аналитический профиль на входе: `phi_1` сам
  по себе даёт параболу (0 у стенки, максимум в центре сечения), а домножение на
  `norm_in` разворачивает вектор скорости строго по нормали к плоскости входа.
  `Q / S` — фиксированный расход на единицу площади входа (не зависит от площади
  конкретного сосуда `s`, поэтому не используется — см. `main.py:Q,S`), делённый
  на `v_mean` — характерную скорость геометрии, чтобы разные по масштабу сосуды
  попадали в один диапазон значений для сети.
  В сумме: нулевая скорость на стенке (условие прилипания) и параболический
  профиль, направленный по нормали, на входе.
- Для давления используется аналитическая функция расстояния до плоскости выхода:
  `signed_dist = (x - center_out) · norm_out`, `p = p_pred * signed_dist * 10`.
  На выходе давление точно равно нулю; так как в residual-лоссе участвует только
  градиент давления, абсолютное значение неважно — для физичного поля давления
  к результату нужно прибавить константу `p_0`.

Функции `phi_1`/`phi_2` сами по себе не считаются аналитически на лету (точное
расстояние до треугольного меша не дифференцируемо и дорого) — вместо этого их
**приближение** предвычисляется офлайн (`modules.point_to_triangles_distance`,
`modules.calc_phi`) и сеть учится его регрессировать (MSE), получая гладкую и
дифференцируемую аппроксимацию.

### Параметризация геометрии трансформером

Чтобы одна модель работала для разных сосудов, точки одной геометрии (внутренняя область +
стенки + вход + выход + внешняя область, см. ниже) обрабатываются трансформером
в одном контексте: энкодер видит всё облако точек сразу, поэтому геометрия
учитывается через attention по самому облаку, а не через отдельный эмбеддинг
геометрии. Архитектура — энкодер-декодер, по мотивам
[PINNsFormer](https://github.com/AdityaLab/pinnsformer) (ICLR 2024). В коде
(`main.py:GAPinn`) энкодер и декодер (`decoder_phi`) общие для обеих веток;
расходятся только финальные линейные головы: `linear_out_phi` (phi_1, phi_2),
`linear_out_v` (компоненты скорости), `linear_out_p` (давление). Есть
закомментированный `decoder_flow` — задел на раздельные декодеры, сейчас не
используется т.к. сложно оптимизируется.

### Два этапа обучения

1. **Phi-этап** (`i < PHI_EPOCHS`): в основном MSE-регрессия `phi_1`/`phi_2` на
   предвычисленное приближение расстояния (`loss_phi`, оптимизатор
   `optimizer_phi`: `linear_emb` + `encoder` + `decoder_phi` + `linear_out_phi`).
   Каждая `DIV_POR`-я обучающая эпоха вместо этого — residual-эпоха только по
   несжимаемости (`div v = 0`), чтобы flow-ветка не стояла на месте. Точки
   внутри области течения на этом этапе сэмплируются из первых 100k (считать расстояния достаточно долго, а на этой стадии плотность точек не критична) закэшированных точек
   (`Dataset.phi_stage = True`).
2. **Flow-этап** (`i >= PHI_EPOCHS`): каждая эпоха — полный residual-лосс
   (3 компоненты уравнения Навье-Стокса + несжимаемость, `modules.calc_res`,
   автоград по координатам `x`, `modules.calc_grad`), оптимизатор `optimizer_flow` (`linear_out_v` +
   `linear_out_p`). При переходе `Dataset.enter_flow_stage()`:
   - выключает 100k-обрезку внутренних точек (сэмплирование из всего облака точек);
   - **сужает датасет только до геометрий, вручную одобренных через
     `select_geometries.py`** (см. `geometry_selection.json`) — т.к. процесс оптимизации PINN очень долгий пока пробуем работать с более простыми геометриями.

### Аугментация точек

Каждый обучающий батч (не валидационный) случайно поворачивается/отражается/
переставляет оси координат — `main.py:run_batches`, матрицы из
`modules.random_rotation_matrices` / `random_reflection_matrices` /
`random_axis_permutation_matrices`, применяются согласованно к точкам, нормалям
и центрам входа/выхода одним и тем же ортогональным преобразованием на элемент
батча (`modules.apply_orthogonal_transform`). Включаются константами
`AUGMENT_ROTATION` / `AUGMENT_REFLECT` / `AUGMENT_PERMUTE`.

## Структура кода

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа обучения: модель `GAPinn`, `Dataset`, двухэтапный цикл обучения, аугментация, интеграция с ClearML. Все гиперпараметры — константы в начале файла. |
| `modules.py` | Переиспользуемые блоки: PDE-компоненты (`calc_grad`, `calc_res`, `zero_loss`), загрузка геометрии из STL и приближённая функция расстояния (`load_stl`, `calc_phi`, `point_to_triangles_distance`, `is_inside`, `sample_boundary_points_from_stl`), быстрый загрузчик для визуализации без phi (`load_geometry_light`), аугментации (`random_rotation_matrices` и т.д.), колбэк чекпоинтов `SaveBest`. |
| `select_geometries.py` | Отдельный интерактивный GUI-скрипт (matplotlib): показывает по одной геометрии, кнопки/клавиши accept(a)/reject(r), пишет решения в `geometry_selection.json` сразу после клика (можно прерывать и продолжать). |
| `augmentation_viz.ipynb` | Загружает одну тестовую геометрию и визуализирует, что делает каждая аугментация (по отдельности и вместе) + численная проверка ортогональности/инвариантности. |
| `history_viz.ipynb` | Загружает `config.json`/`history.json`/`history_val.json` из папки прогона и строит графики train/val лоссов, residual'ов и learning rate. |
| `test_model.ipynb` | Загружает веса `GAPinn` (из ClearML-артефактов или локально), прогоняет на тестовом сплите: `phi` pred vs gt по поверхностям, 3D векторное поле и pred-only визуализация `v`/`p`, MAE по `phi` на всей тестовой выборке. |
| `Clearml_README.md` | Готовые команды ClearML CLI: загрузка/синхронизация датасета, запуск обучения в облаке. |
| `req.txt` | Python-зависимости для окружения ClearML remote-run (torch/CUDA приходят из docker-образа, см. `Clearml_README.md`). |
| `setup.sh` | Bash-скрипт, который ClearML агент выполняет в docker-контейнере перед стартом задачи (сейчас в основном закомментирован). |
| `geometry_selection.json` | Результат работы `select_geometries.py`. |
| `trained_models/<timestamp>/` | Результат одного прогона `main.py` (генерируется локально, в git не хранится) — см. ниже. |

## Структура датасета

```
SimVascDataset/
  <case_id>/                 # один случай/пациент, напр. 0018_H_AO_COA
    <k>_<m>.stl               # "закрытый" меш одного варианта сосуда/ветки — для
                               #   центрирования и классификации точек внутри/снаружи
    <k>_<m>_1.stl              # плоское сечение на одном конце (вход или выход)
    <k>_<m>_2.stl              # плоское сечение на другом конце
    <k>_<m>_3.stl              # боковая поверхность стенки (без торцов)
    <k>_<m>_interior.pt        # закэшированное облако точек внутри сосуда (torch tensor)
    <k>_<m>_outerior.pt        # закэшированное облако точек снаружи (в bounding box) —
                               #   "отрицательные" точки для функции расстояния
    <k>_-1.stl                 # Исходный файл с моделью фрагмента 
                               #   сосудистой системы человека —                          
                               #   из него были нарезаны <k>_<m>.stl
```

`_interior.pt`/`_outerior.pt` генерируются один раз через
`modules.load_stl(..., gen_p=True)` (см. `GEN_POINTS` в `main.py`) — без них
файл `<k>_<m>.stl` не подхватится ни `Dataset`, ни `select_geometries.py`.

Один `<case_id>` может содержать несколько вариантов `<k>_<m>` (разные ветки
сосуда) — это и есть "варианты геометрии", которые размечает
`select_geometries.py`. Каждый вариант используется в обучении дважды — вход и
выход меняются местами (`Dataset.__len__ = len(self.data) * 2`), так что модель
учится на потоке в обе стороны.

Внутри одного сэмпла точки размечены по типу (`x_label`, см. `Dataset.__getitem__`):
`0=interior, 1=walls, 2=inlet, 3=outlet, 4=outerior`, количество точек каждого
типа — константы `INTERIOR_SIZE`/`WALLS_SIZE`/`INLET_SIZE`/`OUTLET_SIZE`/`OUTERIOR_SIZE`
в `main.py`. Эта разметка учитывается в модели посредством `label_emb = self.embedding(x_label)`.

`geometry_selection.json` — плоский словарь `{"case_id/k_m.stl": "accept"|"reject"}`,
пишется `select_geometries.py`, читается `main.py` при переходе на flow-этап
(`Dataset.enter_flow_stage`).

`trained_models/<timestamp>/` (создаётся `main.py` на каждый запуск):
`config.json` (снапшот всех констант запуска), `model.pth`/`model_best.pth`
(последний / лучший по `res_sum` чекпоинт), `optimizer_phi.pth`/`optimizer_flow.pth`,
`history.json`/`history_val.json` (кривые обучения).

## Запуск обучения

1. **Зависимости**: `pip install -r req.txt` + PyTorch с CUDA (для remote-run
   через ClearML используется готовый docker-образ, см. `Clearml_README.md`).
   Для `select_geometries.py` и ноутбуков дополнительно нужен `matplotlib`.

2. **Датасет**: либо локально в `SimVascDataset/` (структура выше), либо через
   ClearML — датасет `SimVascDatasetFull` в проекте `kornaeva-rnf/GA_PINN_3D`
   (команды синхронизации — в `Clearml_README.md`).

3. **(обязательно перед flow-этапом) Отбор геометрий**:
   ```
   python select_geometries.py
   ```
   Пройтись по всем вариантам (Принять/Отклонить или клавиши `a`/`r`), можно
   прерывать и продолжать позже — прогресс сохраняется в `geometry_selection.json`
   после каждого решения. Если к моменту `PHI_EPOCHS` для train- или val-сплита
   нет ни одной принятой геометрии, `main.py` упадёт с понятной ошибкой.

4. **Настройка констант** в начале `main.py` (без CLI-аргументов, всё через
   константы файла):
   - `LOCAL` — запуск кода локально или через ClearML;
   - `USE_CLEARML` — включить логирование/чекпоинты в ClearML (имеет смысл только для `LOCAL=True`);
   - `FULL_TRAIN` — сплит train/val/test по всем директориям датасета
     (`train_test_split`) или маленький фиксированный список для отладки;
   - `PHI_EPOCHS`, `EPOCHS`, `DIV_POR`, `VAL_EVERY`, `B` — расписание обучения;
   - `RESUME_PINN`, `RESUME_TASK` — продолжить с чекпоинта конкретной ClearML-задачи (для локального продолжения без скачивания чекпоинта с ClearML нужно дописать код);
   - `AUGMENT_ROTATION`, `AUGMENT_REFLECT`, `AUGMENT_PERMUTE` — аугментации.

5. **Запуск локально** (нужна CUDA-видеокарта):
   ```
   python main.py
   ```

6. **Запуск на ClearML** (удалённо, в очереди):
   ```
   clearml-task --project kornaeva-rnf/GA_PINN_3D --name ga_pinn_3d \
     --script "main.py" --queue <queue_id> \
     --docker "pytorch/pytorch:2.10.0-cuda12.6-cudnn9-devel" \
     --requirements "req.txt" --folder '' --skip-task-init \
     --docker_bash_setup_script setup.sh
   ```
   (точные команды и загрузка датасета — `Clearml_README.md`).

7. **Продолжение обучения**: выставить `RESUME_PINN = True` и
   `RESUME_TASK = '<clearml task id>'` — подтянутся `model.pth`,
   `optimizer_phi.pth`/`optimizer_flow.pth`, `history.json`
   (и `history_val.json`, если есть) из артефактов указанной задачи, обучение
   продолжится с той же эпохи (`complete_epochs` считается по длине `history`).

8. **Результаты и визуализация**: всё пишется в `trained_models/<timestamp>/`
   (и, если `USE_CLEARML=True`, дублируется как артефакты задачи). Кривые
   обучения — `history_viz.ipynb` (указать папку прогона), корректность
   аугментаций — `augmentation_viz.ipynb`.
