# Постановка задачи CFD-расчёта (референс для валидации PINN)

## Зачем

В этом проекте (см. `README.md`) `v` (скорость) и `p` (давление) **не имеют
ground truth** нигде в пайплайне — они обучаются только через residual-лосс
уравнений Навье-Стокса (`modules.calc_res`), без явной супервизии полем
скорости/давления. `phi_1`/`phi_2` (расстояние до границ) — единственное поле
с GT, и то приближённое (см. `README.md` → «Идея и методология»).

Задача этого документа — сформулировать классический CFD-расчёт (например, в
OpenFOAM или аналоге) **с теми же уравнениями, свойствами жидкости и
граничными условиями**, что заложены в PINN, на тех же геометриях, чтобы
получить независимое решение `v(x)`, `p(x)` и использовать его как ground
truth для количественной валидации.

## Уравнения

Стационарные несжимаемые уравнения Навье-Стокса для ньютоновской жидкости,
без объёмных сил (нет члена силы тяжести):

```
ρ (v·∇)v = -∇p + μΔv     (импульс, 3 компоненты)
∇·v = 0                   (несжимаемость)
```

Ровно то, что реализовано в `modules.calc_res` (форма поделена на ρ):

```
(v·∇)v_i - (μ/ρ)Δv_i + (1/ρ)∂p/∂x_i = 0,   i = 1,2,3
∇·v = 0
```

Других членов (нестационарность ∂v/∂t, турбулентность, объёмные силы) в
модели нет — течение стационарное, ламинарное (см. ниже про Re), без гравитации.

## Свойства жидкости

Жёстко заданы в `modules.py:calc_res` (аппроксимация крови как ньютоновской
жидкости):

| Параметр | Значение | Код |
|---|---|---|
| Динамическая вязкость μ | 3×10⁻³ Па·с (3 мПа·с) | `modules.py:19` |
| Плотность ρ | 1050 кг/м³ | `modules.py:20` |

## Геометрия

Источник — `SimVascDataset/<case_id>/<k>_<m>*.stl` (см. `README.md` →
«Структура датасета»). На каждый вариант `<k>_<m>` уже готовы три открытые
поверхности одного замкнутого объёма:

- `<k>_<m>_3.stl` — боковая стенка сосуда;
- `<k>_<m>_1.stl`, `<k>_<m>_2.stl` — плоские сечения на двух концах.

Их можно напрямую использовать как именованные патчи при построении объёмной
сетки (стенка / вход / выход) — не нужно ничего вырезать заново.

**Единицы**: координаты STL — миллиметры. Для решателя переводить в СИ
(метры), так как μ/ρ выше уже в СИ.

**Направление потока**: PINN обучается на каждой геометрии в обе стороны —
основное направление `_2.stl` = вход, `_1.stl` = выход (`odd=False`,
дефолт везде в коде), обратное — вход/выход меняются местами.

**Какие геометрии считать**: В равном количестве из разных выборок (представлены в `debug_split.json`) геометрии, отмеченные `accept` в `geometry_selection.json`.

## Граничные условия

- **Стенка** (`_3.stl`): условие прилипания, `v = 0`.

- **Вход** (по умолчанию `_2.stl`): скорость направлена строго по внутренней
  нормали к плоскости входа, профиль — полностью развитый (пуазейлевский,
  параболический: 0 у стенки, максимум на оси), со средним по сечению модулем
  скорости:

  ```
  V_in = Q / S = 1.5e-6 / 2e-6 = 0.75 м/с
  ```

  (`Q`, `S` — константы `main.py:33-34`). **Важно**: это фиксированная скорость
  на единицу площади, одинаковая для всех геометрий, **не** зависящая от
  реальной площади конкретного входа — так сейчас устроен BC в PINN (см.
  `README.md`, формула `v = v_pred·φ₂ + φ₁·norm_in·(Q/S/v_mean)`, где `Q·(s/S)/s`
  сокращается до `Q/S`). Это намеренное упрощение текущей модели, а не
  ошибка — воспроизводить нужно именно так, а не расход, пропорциональный
  реальной площади входа. Точная форма профиля в PINN — гладкая
  распределённая аппроксимация расстояния до стенки (не строгая парабола);
  для CFD-референса достаточно стандартного пуазейлевского профиля с тем же
  средним модулем скорости — это физически корректнее и не требует
  воспроизводить именно PINN-аппроксимацию.

- **Выход** (по умолчанию `_1.stl`): условие по давлению, `p = 0` (референсное,
  относительное). Абсолютное значение неважно ни в PINN, ни в CFD-сравнении —
  сравнивать нужно **поле давления с точностью до аддитивной константы**
  (градиент/относительные перепады, а не абсолютные числа).

## Режим течения

Модель не содержит турбулентных членов — течение ламинарное. Перед расчётом
стоит оценить число Рейнольдса на входе для каждой геометрии:

```
Re = ρ · V_in · D_h / μ,   D_h — гидравлический диаметр входного сечения
```

При референсной площади входа `S = 2e-6 м²` (`D_h ≈ 1.6 мм`) получается
`Re ≈ 420` — ламинарный режим правдоподобен для большинства геометрий, но
конкретные входные сечения в датасете отличаются по размеру, так что имеет
смысл проверить `Re` по факту для каждой геометрии и явно отметить исключения
(если найдутся), а не считать все геометрии ламинарными по умолчанию.


## Что нужно на выходе

1. Полное объёмное решение (`v`, `p`, `x`) в виде тензоров.
2. Задача интерполяции решения на соседние точки не рассматривается т.к. PINN может выдавать решение в любых точках, в частности используемых решателем.
3. Для каждого расчёта указать `Re`, тип сетки/решателя и любые
   отклонения от постановки выше (если пришлось скорректировать BC/режим для
   конкретной геометрии).
